# Filesystem contract — 0.1 candidate

## Boundaries and storage

Ordinary explicitly selected local directories and regular files, on the same local volume as the store. Production default: ~/Library/Application Support/TryFolder/Sessions. Development/test store may be explicitly supplied with --store; no silent relocation. The source and every managed content root must be disjoint. Validate components, device/inode identities and no-follow traversal. Reject missing/replaced roots. Never act on a URL trusted only because a persisted JSON says so: session content paths derive from a validated UUID in a verified store.

Reject symlinks, hard links, special files, nested devices, cloud-managed locations/placeholders, application bundles/libraries, live-database extensions, protected system/account/application roots. Exclude Finder .DS_Store metadata, .git, node_modules, .build, build, dist, DerivedData, .venv, venv, __pycache__ with explicit path/reason records. Do not traverse exclusions. Excluded descendants can never be deleted by parent operations. Empty directory deletion is conservative; ordinary tracked file operations are the unit of Apply. Reject ambiguous case/Unicode collisions and case-only rename plans until independently verified.

## Capture and metadata

Source → validated baseline → draft. Scan before and after capture; compare copied bytes and source identity; bounded retries or busy error. SHA256 in chunks. The implemented backend performs full, streaming regular-file copies with metadata preservation and post-copy verification. Copy-on-write cloning is deferred; no clone-speed or zero-storage claim is made. Preserve regular-file mode, extended attributes (including resource forks/quarantine), timestamps and supported flags; reject flags/ACLs that cannot be safely handled. Compare bytes, mode and xattrs. UF_TRACKED document identity is allowed and preserved on independent copies but excluded from semantic fingerprints: APFS atomic swaps preserve pathname tracking independently of the content inode. Apply/Undo leave that native pathname behavior intact. All other file flags are rejected. Ignore access time and inode changes for semantic diff; device/inode remain guards. Creation/modification timestamps are preserved when copying but timestamp-only touches need not be semantic changes. Directory metadata is outside Apply's scope and must be documented.

## Lifecycle and sealing

Preparing → Editing → Reviewing → ReadyToApply/Conflict → Applying → Applied; errors during mutation → RecoveryNeeded; recover only from journals with validated paths. Undo is a separate guarded transaction returning Editing after success; Discard only in nonmutating states with no unresolved journal. Keep exports may succeed even when the source is missing/conflicted. Export stable sealed bytes to a nonexistent explicit destination outside source/store/all managed trees. Never overwrite/merge. No export destination is cleanup-owned. Discard is reversible logical archival retaining session bytes, not broad deletion.

A review captures an application-controlled snapshot, its manifest, source observations and per-path three-way results. No claim of tamper-proofing. Validate the sealed snapshot before export/apply. A changing live draft cannot change reviewed bytes. UI explicitly labels sealed review and asks for refresh to include newer edits. Original status is timestamped observations, not continuous guarantees.

## Mutations and durability

Actor serializes state; a fixed per-user coordination directory at ~/Library/Application Support/TryFolder/Coordination holds an interprocess flock guard and durable reservations across independent stores. The guard spans validation, journaling, operations and verification. Interrupted transactions retain source/ancestor identity reservations until guarded recovery completes. Inaccessible owners are not silently pruned. Tests may supply TRYFOLDER_COORDINATION_ROOT, but all cooperating processes must use the same coordination domain. Anchor reads/writes to directory descriptors, O_NOFOLLOW and descriptor-relative operations. Revalidate ancestor identities at mutation boundaries; never follow a swapped symlink. Do not recursively remove/replace user directories.

Apply takes exact review ID and explicitly selected relative paths. Conflicting paths cannot be selected; user can keep current original by deselecting, or export draft. Replacement of conflicted source is deferred (new baseline/review required). Save/close external editors first. Preserve verified recovery bytes for each overwritten/deleted file, stage replacements, fsync durable journal before mutations, journal attempted/applied/verified. Use no-clobber renames for additions. Capture existing files without following links before replacement. File-by-file transaction, not whole-folder atomic. Stop on ambiguity and retain baseline/review/recovery. A crash after mutation but before record is resolved from actual state, idempotently. Undo must compare current state to receipt expected poststate, preserving later edits as conflict. NSFileCoordinator is only cooperative; same-user hostile processes, disk loss and arbitrary concurrent writes remain practical limits.

## Public interface (owned by root)

`public actor SessionEngine` with `init(storeURL: URL) throws`; methods `listSessions() throws -> [SessionRecord]`, `create(source: URL) throws -> SessionRecord`, `review(sessionID: UUID) throws -> ReviewRecord`, `loadReview(sessionID: UUID) throws -> ReviewRecord?`, `apply(sessionID: UUID, reviewID: UUID, selectedPaths: Set<String>) throws -> SessionRecord`, `undo(sessionID: UUID) throws -> SessionRecord`, `recover(sessionID: UUID) throws -> SessionRecord`, `discard(sessionID: UUID) throws -> SessionRecord`, `keep(sessionID: UUID, reviewID: UUID, destination: URL) throws -> URL`. Actor methods awaited by app. Public model definitions in Sources/TryFolderCore/Models/Contracts.swift. Errors are LocalizedError with concrete affected path. Tests may use explicit fault injection agreed with filesystem owner. App never directly mutates source/session bytes.

## Release gates

A: isolate/capture/exclusion/path/metadata behavior proven. B: real native select/create/edit/review/keep/discard, relaunch. C: selected add/edit/remove, source conflicts, sealed bytes, fault boundaries, recovery/undo, later-edit protection, concurrency. D: native smoke, measurement, bundle, accurate docs/demo. At most two review/fix rounds per milestone except concrete data-loss defects. No public Apply/Undo enabled if C does not pass; deliver accurately labeled draft alpha then preserve blocked C work.
